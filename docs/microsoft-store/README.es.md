## Paquete preparado

Se incluye un manifiesto parametrizable y `build-msix.ps1`. El script:

1. exige los tres campos exactos de Partner Center y rechaza valores de ejemplo;
2. comprueba que `package.json`, `tauri.conf.json` y `Cargo.toml` tengan la misma versión;
3. guarda registros de `npm ci`, `npm test`, compilación Tauri y `MakeAppx`, además de las versiones de Node.js, npm, Rust, Cargo, Tauri CLI y MakeAppx;
4. compila directamente el ejecutable anfitrión en Windows x64, sin generar otro instalador NSIS/MSI, genera iconos de MSIX/Store a partir del SVG original y empaqueta `SemanaAlPlato.exe` y las DLL de salida;
5. genera un `.msix` sin firma y un `.msixupload` ZIP que contiene ese MSIX, sin `.appxsym`;
6. calcula SHA-256 de ambos artefactos y los registra en `BUILD-METADATA.txt`.

El artefacto de Actions run [42590341105](https://github.com/SenecaDPJ/Semana-al-plato/actions/runs/42590341105), desde `02adc670d3284fb2d3b307383cf40203feffecec`, se generó **antes** del ajuste del mínimo. Incluye `Semana-al-Plato_2.2.0.0_x64.msix` (SHA-256 `e5da0d373c2106aea894f4ed4b8c01a09bf48858cf3321de7e201e43b8ed074d`) y `Semana-al-Plato_2.2.0.0_x64.msixupload` (SHA-256 `4bd3d087593ecd676b94247c8ac7843b7995b0368f87e2b24cd7fc1d303d0ada`). El ZIP de Actions es el artefacto `13660379174`, pesa 6.576.381 bytes, SHA-256 `11375f21b8e5bcd407e21162cd96e676f6af0d86a63cdc8a432dfb0c530a1428` y caduca el 23 de noviembre de 2026. La compilación limpia, `npm test` (30/30) y `MakeAppx` pasaron con el manifiesto anterior, que declaraba `MinVersion=10.0.22000.0`. Este MSIX no es el artefacto final de la rama tras el cambio de mínimo, no lleva firma y no se instaló directamente.

El artefacto de Actions de 2.2 contenía, fuera del MSIX, ambos paquetes, iconos, logs, `BUILD-METADATA.txt` e inventario/licencias de Cargo. La candidata 2.3.0.0 del run 42812887051 incluye dentro del MSIX `THIRD-PARTY-NOTICES.txt`, el inventario CSV y el resumen JSON. El grafo x64 MSVC contiene 247 crates; el inventario de esa candidata registra 440 archivos, incluidos 7 suplementos para 6 paquetes. La auditoría recursiva de las fuentes encontró tres textos legales anidados que no llegaron a esa candidata; el exportador ya está corregido, pero hace falta generar y probar una versión con payload único antes de distribuir. El cribado de expresiones y textos está documentado; la revisión humana de menciones de cabecera y la autorización legal siguen pendientes en [LICENSE-REVIEW-2.3.0.0](LICENSE-REVIEW-2.3.0.0.es.md). El inventario no es autorización legal. El MSIX de Store permanece sin firma; Microsoft lo firma al completar la certificación.

La plantilla marca `runFullTrust` porque esta aplicación de escritorio necesita proceso de confianza plena. No incluye `unvirtualizedResources` ni otras capacidades. El manifiesto fuente declara ahora `MinVersion=10.0.26100.1742` y `MaxVersionTested=10.0.26300.0`. El WACK más reciente se ejecutó sobre la candidata 2.3.0.0 que declara ese mínimo; véase el resultado actualizado en la tabla de pruebas.

Los parámetros opcionales `-MinVersion` y `-MaxVersionTested` permiten fijar los builds respaldados por pruebas. El mínimo predeterminado es `10.0.26100.1742`, exacto del sistema donde se completó la prueba funcional LTSC; el MSIX con este mínimo se reconstruyó, instaló y abrió en ese sistema, y el usuario confirmó la persistencia de sus datos tras reabrirlo. `MaxVersionTested` predeterminado sigue en `10.0.26300.0`, que consta en el último WACK. Esta evidencia no demuestra compatibilidad con otros builds o ediciones y no sustituye WACK ni la certificación de Store.

### Ejecutar la generación en Windows x64

Requisitos: Node.js 22, Rust estable con MSVC, Visual Studio C++ Build Tools, Windows SDK con `MakeAppx.exe` y dependencias descargables. La generación se puede repetir desde la rama y no ejecuta el EXE. El flujo usa `windows-latest` y Rust `stable`; registra las versiones concretas en cada artefacto, pero no garantiza builds bit a bit idénticos entre ejecuciones.

🔴 EJECUCIÓN⚙️🚨 — Compila, ejecuta las pruebas automatizadas y crea los paquetes en `artifacts/msstore/`. Puede descargar dependencias de desarrollo y deja registros locales. Los valores que facilitaste ya aparecen en el workflow; para una ejecución local puedes usar estos datos o copiar cualquier cambio posterior de Partner Center.

```powershell
.\docs\microsoft-store\build-msix.ps1 `
  -PackageIdentityName "SenecaDPJ.Semanaalplato" `
  -PackageIdentityPublisher "CN=6F3CA482-2B0E-4C58-95F1-BFA42598F4C9" `
  -PublisherDisplayName "SenecaDPJ"
```

El script se detiene si falta Node/Rust/SDK, si las versiones discrepan o si ya existe la carpeta de salida; no sobreescribe paquetes anteriores. No crea ni solicita certificados o claves privadas. La `.msixupload` contiene el paquete MSIX y no símbolos de depuración; Partner Center puede aceptar el `.msix` directamente, aunque Microsoft recomienda el formato de subida para Store.

El workflow `Build Microsoft Store MSIX (manual)` genera un artefacto al subir cambios que afecten al código, scripts o manifiesto de empaquetado de esta rama; la retención es de 14 días. El script exporta el inventario Cargo y los avisos antes de crear el MSIX, y los incluye dentro del paquete junto con el CSV y el resumen; también conserva el bundle de revisión fuera del MSIX. Los valores de identidad predeterminados son los que facilitó el usuario. La ejecución manual desde GitHub requiere que el workflow esté en la rama predeterminada; después se puede elegir esta rama como referencia. El workflow no publica una release ni envía el producto a certificación y no sustituye pruebas funcionales o WACK.
